Speaker · 1:25–2:25

“The extension collects page signal types, not field values. It combines local heuristics with an optional Google Safe Browsing URL lookup. When the assessment should warn, the extension shows an in-page warning where content-script access is available, and uses an extension-owned warning page when it is not. Incident persistence: `chrome.storage.local` stores incidents and pending warning state. Incident writes are serialized to avoid concurrent updates replacing one another.

Example: HTTPS malware.wicar.org → 45 points / Medium from the host keyword; local elevated-risk rule makes it warning-eligible. A Safe Browsing match adds 70 more. HTTP adds its own transport weight.

LIMITS + TAKEAWAY
A practical, privacy-minded boundary

Support recovery without claiming certainty.

Local by default
History + incidents stay in extension storage

Optional email requires the user to configure a separate relay; it is off by default.

Clear data boundary
No form values

Page field types are signals. Optional Safe Browsing sends the page URL to Google.

Known limits
Not a file scanner

Heuristics are indicators, not proof. The extension cannot observe Chrome interstitial bypasses.

Assess → Warn → Record → Recover
Keep the risk context available after the user’s choice.
Speaker · 5:50–7:00

“Threat Recovery is a support layer, not a guarantee that every threat will be detected. Local field-type heuristics can be wrong; Safe Browsing is optional and receives the URL when enabled. We do not scan downloaded files or observe bypasses of Chrome’s own interstitial. History and incidents stay in local extension storage by default. Optional high-risk email needs a user-configured HTTPS relay and is off by default. Our outcome is simple: assess, warn, record the choice, and give the user something useful to do afterward. Thank you.”

Q&A · 3 MINUTES
Likely questions · concise, accurate answers

Be clear about what is implemented.

Is storage persistent?

Yes in the current source: incidents and pending warning data use `chrome.storage.local`. Incident writes are serialized. Runtime behavior should still be confirmed in the installed extension.

Why did WICAR show low · 25 before?

That reading does not match the current heuristic source. Current HTTPS malware.wicar.org adds a 45-point threat-keyword signal. The old reading may have come from a stale bundle or earlier code; the screenshot alone cannot identify which.

Does every warning create an incident?

No. The incident is saved only when the user chooses “Continue anyway” in Threat Recovery’s warning. Choosing Leave does not create one.

Does a Safe Browsing match always warn?

Yes, in current assessment logic. A match adds 70 points and sets `shouldWarn`, even when local heuristics alone would not reach the threshold.

Are form contents collected?

No. The extension detects field types and permission states, not entered values. Safe Browsing URL lookup sends the URL to Google when configured.

What is not covered?

Downloaded-file scanning, Chrome interstitial bypass detection, and an included email relay. The optional email path needs the user’s own relay.

Presenter check before the event: reload the unpacked extension, run the local demo, and confirm the warning, “Continue anyway,” and dashboard incident in the same browser profile.
Q&A · 7:00–10:00
